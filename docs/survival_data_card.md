# Survival Data Card (review item P1 10)

What the Cox PH model is trained on. Source: the latest training dataset of each brand in `data/processed/` (`dataset` column below), the same rows as the LightGBM model. Generated by `src/models/survival_card.py`.

## 1. Definition

| Item | Definition |
|---|---|
| Unit | One player on one cutoff (the first day of a month). The same player can appear in several cutoffs. |
| Population | Players with at least one bet in the 30 days up to the cutoff, included (`churn_labels.population`). |
| Time origin | The cutoff (day 0). Every player enters on day 0, active. |
| Event | The start of the first silence of 60 days or more after the cutoff: the last bet before it (day 0 if the player has no bet after the cutoff). The same 60-day inactivity as the churn label. |
| `duration_days` | The day of the event, or, if censored, the last day with a bet. |
| `event_observed` | 1 if the 60-day silence ends on or before the data end (2026-10-06); 0 if censored. |
| Censoring | Administrative only: the data end. A player whose last bet is less than 60 days before the data end is censored at that last bet. It does not depend on the player, so it is not informative. |

## 2. Right censoring and left truncation

- **Right censoring.** The later the cutoff, the shorter the follow-up, so the censoring rate grows from the first to the last cutoff (table below). Cox PH handles this through `event_observed`. The 30-day probability used in `value_at_risk_30d` only needs the first 30 days; every cutoff of the dataset has at least 60 days of follow-up, so all the events up to day 30 are observed.
- **Left truncation (delayed entry).** There is none on the time scale of the model: time counts from the cutoff, and every player enters on day 0. A player who stopped before the cutoff is not in the population of that cutoff; this is the definition of the population, not a truncation of the follow-up.
- **Where the data start matters: the history features.** The source tables start on 2025-04-01. Tenure (`days_since_first_bet`) is capped at 150 days, so it means the same on every cutoff from 2025-08-29 on ("150 days or more"). On earlier cutoffs (the first training months of the backtest), players who started before the data look younger than they are. The 180-day history windows are complete only from 2025-09-28. The longest window of the other features, 90 days, is always complete.
- **Consistency with the churn label.** `event_60d` = 1 must mean the event on day 0 and observed. Share of rows where this holds: column `Label check`.
